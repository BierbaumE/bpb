# bpb – Dach-Seite BierbaumPerformanceBrothers

Cloudflare Worker (`worker.js`) mit statischen Dateien aus `public/`. Die Seite ist noch im Aufbau und liegt hinter einem Passwort.

- Adresse: `https://bierbaumperformancebrothers.com` (und `www.`), Vorschau `https://bpb.bpbrothers.workers.dev`
- **Zugang:** `worker.js` zeigt ohne Cookie nur den Platzhalter (`public/platzhalter/`) mit Login-Knopf; öffentlich sind nur die Pfade in `OEFFENTLICH` (Login, Platzhalter-CSS, Favicon, `logo-dach.svg`, robots). Nach dem Passwort (Hash im Code, nie das Passwort) folgt die Seite im Aufbau. Alles `noindex`, bis die Seite öffentlich geht.
- Seiten: `public/index.html` (Startseite), `public/bytes/`, `public/bauhof/`, `public/brain/`, `public/bolide/` (Bereichsseiten, Platzhalterinhalt; Bytes = Entwurf C), `public/impressum/` und `public/datenschutz/` (Entwürfe, allgemein formuliert, Klammern orange; Quelle sind die Entwürfe im Projekt), `public/platzhalter/`.
- **AGB und AVV stehen bewusst nicht auf der Seite**; sie kommen erst im Bestellvorgang (Link + Checkbox).
- Keine externen Schriften, Skripte oder Tracker (kein Cookie-Banner nötig); CSP in `worker.js` und `public/_headers`.
- Deploy: Workers Builds aus diesem Repo (Branch `main`), Konfiguration in `wrangler.toml`.
- Später: Verzeichnis-Seite aus `portfolio.json`, siehe `claude/KONZEPT-BPB.md` Abschnitt 4a. Vor der Veröffentlichung: Impressum/Datenschutz füllen und in `OEFFENTLICH` aufnehmen, Login und `noindex` entfernen.

## Login der Seite im Aufbau (aus `claude/TECHNIK.md` im Projekt „App+HP Entwicklung“ übernommen, 23.10.2026; hier weiterpflegen)
- Öffentlich zeigt `/` nur den Platzhalter („Hier entsteht eine neue Seite.“, `public/platzhalter/`) mit kleinem „Login“-Knopf oben rechts. Alle anderen Pfade leiten ohne Anmeldung still auf `/` um.
- `/login` ist eine eigene Seite mit Passwortfeld. Falsches Passwort zeigt die Meldung „Das Passwort stimmt nicht. Bitte noch einmal versuchen.“ auf der Seite, kein Browser-Dialog. Die Eingabe wird mit `trim()` bereinigt, das Feld hat `autocapitalize="none" autocorrect="off" spellcheck="false"`.
- Richtiges Passwort → Cookie `bpb_zugang` (30 Tage, HttpOnly, Secure, SameSite=Lax; Wert = SHA-256 aus Passwort-Hash und Zusatz) und die Seite im Aufbau. `/logout` löscht das Cookie (noch kein Knopf).
- `worker.js` läuft vor den statischen Dateien (`main = "worker.js"`, `[assets] binding = "ASSETS"`, `run_worker_first = true`). Im Code steht nur der SHA-256-Hash, **das Passwort steht nirgends im Projekt oder Repo**. Ändern = neuen Hash in `worker.js`, pushen; alle bisherigen Cookies werden damit ungültig.
- `public/bytes/` = Entwurf C „Nacht“ (früher `/digital/`, Commit `3b94b76`, 19.10.): Systemschriften statt Google Fonts (CSP `style-src 'self'`, keine Inline-Styles), Demo-Links auf die neuen Adressen, „Über uns“/Kontakt noch Platzhalter.
- Gilt auch für `bpb.bpbrothers.workers.dev`. Es ist nur eine Hürde gegen zufällige Besucher; `noindex` bleibt (Meta, robots.txt, Header). CSP in `_headers`: keine externen Schriften, Skripte oder Tracker; BPBytes nutzt Systemschriften.
- **Vor der Veröffentlichung entfernen:** `worker.js` löschen, `main`, `binding` und `run_worker_first` aus `wrangler.toml` nehmen; `public/platzhalter/` entfällt.
- **Stolperstein Builds:** Workers Builds startete beim Repo `bpb` teils erst nach ein bis zwei Stunden (bei GitHub bis dahin keine Check-Runs). Was wirklich ausgeliefert ist, zeigt `workers_get_worker_code` (Skript `bpb`) oder Dashboard → Workers & Pages → `bpb` → Einsätze.
